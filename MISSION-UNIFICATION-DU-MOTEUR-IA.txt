PROBLÈME RACINE
L'application possède TROIS systèmes de contexte IA concurrents qui ne se
connaissent pas :
  (A) buildCtx()               l.3768  — riche, alimente l'ancien askAI/Groq
  (B) prepareAIPayload()       §C      — routeur ALADDIN HOME/ANALYSE/PRÉVISIONS
  (C) buildContextPayload() + buildScopedPayload(detectScope())  l.8182/8288
      injectés par l'intercepteur window.fetch l.8342 — UNIQUEMENT sur Groq
Résultat : Gemini (chemin principal) ne reçoit jamais le scoping par écran,
Groq reçoit deux "uniques sources de vérité" contradictoires, et l'accueil
n'a aucune ancre temporelle.

OBJECTIF
Une seule couche de contexte, un contrat explicite par écran, une
invalidation pilotée par les données. Ne casse aucune fonctionnalité
existante : tu unifies, tu ne supprimes pas de fonctionnalité utilisateur.

------------------------------------------------------------------------
§1 — COUCHE UNIQUE : buildLiaContext(viewType, opts)
------------------------------------------------------------------------
Crée UNE fonction canonique, placée juste avant prepareAIPayload() :

  window.buildLiaContext = function(viewType, opts = {}) => {
    meta, temporel, cadrage, donnees, anomalies, contrat
  }

1.1  meta : { viewType, generatedAt (ISO), signature (cf. §5), devise,
             langue, provider: 'gemini'|'groq', version: '9.4.0' }

1.2  temporel (bloc buildTemporalCore(), TOUJOURS présent, toutes vues) :
     dateAujourdhui (fr-FR long), dateISO, heure "14h05", jourSemaine,
     momentJournee (matin|midi|apres-midi|soiree|nuit),
     nbTxAujourdhui, depensesAujourdhui, revenusAujourdhui,
     txAujourdhui[] {heure, montant, type, categorie, note, humeur},
     aucuneSaisieAujourdhui, derniereSaisieDate, joursSansSaisie,
     alerteSilence (>=2j), silenceCritique (>=5j), nbTxTotal
     Source unique : window.txs / window.cur() (pont d'état l.2554).

1.3  cadrage : { fenetre, perimetre, comparatif, interdits[] }
     C'est le contrat analytique de l'écran (cf. §3). Il DOIT être sérialisé
     dans le JSON envoyé au modèle, pas seulement dans le system prompt.

1.4  donnees : le contenu métier de l'écran (reprend les case existants de
     prepareAIPayload, enrichis comme indiqué au §3).

1.5  anomalies : detectAnomalies() — inchangé, priorité absolue.

1.6  contrat : { longueurMax, tonalite, formatSortie, tokens }
     Une seule autorité sur la longueur et le format. Aucun appelant n'a
     plus le droit de redéfinir la longueur dans son userQuery (cf. §4).

prepareAIPayload() devient un simple adaptateur qui appelle
buildLiaContext() et retourne {contextData, anomalies, systemFocus, query}
pour ne pas casser buildAladdinSystemPrompt().

§3 — CONTRATS PAR ÉCRAN (le cœur de la demande)
------------------------------------------------------------------------
Chaque viewType reçoit exactement sa fenêtre, son périmètre, ses interdits.

[ACCUEIL] viewType 'HOME'
  fenetre    : "AUJOURD'HUI, heure par heure"
  perimetre  : solde actif, txAujourdhui[], échéances récurrentes <7j,
               prochain revenu attendu (cycle), objectif prioritaire
  comparatif : 7 jours glissants {depenses7j, revenus7j, nbTx7j} — référence
               uniquement, jamais sujet principal
  interdits  : inventer une dépense absente de txAujourdhui ; commenter le
               mois ; citer un chiffre absent du JSON ; produire un rapport
  contrat    : 3 phrases max, ton ami direct, tokens 320
  règle spéciale : si nbTxAujourdhui === 0 → le dire explicitement.
               Si alerteSilence → le silence devient le sujet UNIQUE.
  Remplace budgetSemaineRestant par budgetSemaineRestant_estime et
  documente dans le JSON qu'il dérive de inc30/4 (approximation).

[ANALYSE] viewType 'ANALYSE'
  fenetre    : opts.period || window.analyticsPeriod ('day'|'week'|'month'|'year')
               + libellé humain via periodLabel()
  perimetre  : getPeriodTxs(period) + getPrevPeriodTxs(period) pour le delta,
               top catégories, notes, humeurs, virements de LA PÉRIODE
  comparatif : période précédente uniquement (pctChange)
  interdits  : élargir hors de la période sélectionnée sauf pour un pattern
               historique explicitement étiqueté "historique long terme"
  contrat    : 2 à 3 phrases pour la carte d'insight, tokens 400
  IMPÉRATIF  : la période est PASSÉE EN PARAMÈTRE, jamais relue implicitement.
               callAladdinAI('ANALYSE', q, {period: p})

[PRÉVISIONS] viewType 'PRÉVISIONS'
  fenetre    : prospectif 30 / 90 / 180 jours, ancré sur temporel.dateISO
  perimetre  : scénarios choc/actuel/optimal, date de passage sous zéro,
               récurrences <30j, top 5 leviers, cycle de revenu
  interdits  : projeter sans citer la date de départ ; annoncer une date
               qui ne dérive pas de dateISO
  contrat    : 5 sections numérotées, tokens 2000
  → aligne le userQuery de la l.9238 sur ces 5 sections (supprime le
    "Max 5 lignes total" qui contredit le systemFocus).

[SANTÉ FINANCIÈRE] viewType 'SANTE_FINANCIERE'
  fenetre    : structurel 30 jours + trajectoire objectifs
  perimetre  : axes du score, benchmarks (réserve 3-6 mois, rétention 20-30%)
  contrat    : plan 30/90/180j avec jalons, tokens 1800

[CHAT] viewType 'CHAT'  (nouveau — aujourd'hui le chat emprunte HOME/ANALYSE)
  fenetre    : déterminée par la question via le routeur §F1, mais le
               contexte temporel complet est TOUJOURS joint
  perimetre  : contexte large (équivalent buildCtx) + historique 6 échanges
  contrat    : réponse conversationnelle, tokens 1200
  C'est le SEUL viewType qui reçoit window.aiMsgs.

[CONSEIL] viewType 'CONSEIL'
  cf. §7.

§5 — SIGNATURE DE DONNÉES ET BUS D'INVALIDATION
------------------------------------------------------------------------
5.1  window.liaDataSignature = () => {
       const t = window.txs || [];
       const a = (window.accs||[]).reduce((s,x)=>s+(x.balance||0),0);
       const g = (window.goals||[]).length;
       const last = t[0] ? (t[0].id || t[0].date) : 'none';
       return [t.length, last, Math.round(a), g,
               new Date().toISOString().slice(0,13)].join('|');
     }
     Elle change à chaque transaction, chaque solde, chaque objectif,
     et au moins une fois par heure.

5.2  Tous les caches IA deviennent {value, sig, ts} et ne sont servis que si
     sig === liaDataSignature() ET ts < TTL :
       - _aladdinHomeCache        (accueil, TTL 8 min)
       - _lastInsight             (accueil legacy, TTL 10 min)
       - window['proj_ai_'+period+...] (prévisions — remplace la clé par
         date par une clé par signature)
       - le cache d'analyse s'il existe
     Centralise-les dans window.liaCache = { get(key), set(key,val,ttl) }.

5.3  window.invalidateLiaCache(reason) vide TOUT le registre liaCache et
     journalise la raison. Branche-la sur :
       - sauvegarde / modification / suppression de transaction (~l.7946, 7957)
       - création ou modification de compte, d'objectif, de catégorie
       - changement de devise ou de langue
       - bouton ↻ de l'accueil (l.5075) — aujourd'hui il ne vide que
         _lastInsight et laisse _aladdinHomeCache intact : le rafraîchissement
         est mort sur le chemin Gemini
       - setInterval 10 min (l.7967)
       - retour en ligne (flushIntents)

5.4  Après invalidation sur l'écran actif, relance l'insight correspondant
     (maybeAutoInsight sur home, fetchPeriodInsight sur analytics) —
     un seul appel, débounce 400 ms pour absorber les saisies en rafale.

§6 — SOCLE ANTI-HALLUCINATION (system prompt unique)
------------------------------------------------------------------------
Dans buildAladdinSystemPrompt(), préfixe par "<<LIA_CTX_V1>>" puis un bloc
invariant, identique pour toutes les vues :

  • Toute date que tu cites dérive de temporel.dateISO. Tu ne supposes
    jamais la date.
  • Tout chiffre provient du JSON. Aucun arrondi inventé, aucune estimation
    non étiquetée comme telle.
  • Tu respectes strictement cadrage.fenetre et cadrage.perimetre. Ce qui
    est hors périmètre n'existe pas pour cette réponse.
  • Tu respectes cadrage.interdits sans exception.
  • Si les données sont insuffisantes, tu le dis en une phrase au lieu
    d'extrapoler.
  • Tu respectes contrat.longueurMax. Pas de titres entre crochets.
  • Tutoiement systématique.
Puis les anomalies CRITIQUES, puis le cadrage, puis les données.

------------------------------------------------------------------------
§9 — OBSERVABILITÉ
------------------------------------------------------------------------
window.LIA_DEBUG = false par défaut. Si true, chaque appel journalise :
viewType, cadrage.fenetre, signature, provider, tokens demandés, taille du
JSON, latence, cache hit/miss. Ajoute window.liaInspect(viewType) qui
retourne le contexte complet sans appeler l'API — indispensable pour
vérifier ce que Lia voit réellement sur chaque écran.

------------------------------------------------------------------------
§10 — CONTRÔLES DE NON-RÉGRESSION
------------------------------------------------------------------------
 1. Accueil sans transaction du jour → Lia dit explicitement qu'il n'y a eu
    aucune transaction aujourd'hui et n'infère aucune dépense.
 2. Ajout d'un dépôt → la carte d'accueil se met à jour immédiatement et
    cite le montant exact du dépôt.
 3. liaInspect('HOME') contient temporel.dateISO, temporel.heure et
    cadrage.fenetre.
 4. Boutons jour/semaine/mois/année → donnees.periode et le nombre de
    transactions correspondent exactement au bouton actif.
 5. Une réponse Gemini et une réponse Groq sur la même question citent les
    mêmes chiffres (parité §2).
 6. Aucune requête ne contient deux blocs se déclarant source de vérité.
 7. Prévisions : les 5 sections sont produites, aucune date antérieure à
    dateISO.
 8. Conseil avec une seule clé → 4 tours réels, aucun fallback local.
 9. Badge accueil = GEMINI ✨ quand Gemini répond, LOCAL seulement hors-ligne.
10. Chat IA conserve son historique ; accueil, analyse et prévisions n'en
    héritent plus.
